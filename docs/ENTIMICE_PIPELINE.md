# Entimice API pipeline — build report

Requirement: [`examples/requirements/entimice_api_pipeline_requirement.txt`](../examples/requirements/entimice_api_pipeline_requirement.txt)
Pipeline: `examples/pipelines/entimice_api.yaml` (DAG `examples/dags/pkf_entimice_api.py`)

## What was built

| part | component | how |
|---|---|---|
| trigger | `entimice_selfservice` | `schedule: 0 6,18 * * *`; `selfservice` (control list) → `parse_json` → `selfservice_due` (`force: {force_refresh}`) → `data_vars` |
| source | `entimice_studies` | `type: entimice`; account by destination (`accounts`); `list` the study location, 20 levels, full Entimice paths kept |
| transformation | — | none |
| destination | `entimice_datalake` | bucket per destination (`bucket_map`); `mode: stream` (16 MiB parts, 8 in parallel, HEAD size check, Content-Type by extension, overwrite); `check` → `prefix_by` |
| connection | `entimice_api_connection` | `check_before_run: false` (nothing due → no Entimice or S3 call) |
| pipeline | `entimice_api` | `max_active_runs: 1`, `catchup=False`, run parameter `force_refresh` |

Every part is catalogue steps (no generated code), so every component is `approved` without an AI code review, and
`pkf build entimice_api` builds it.

## Framework changes (needed by the requirement)

The 0.8.2 framework could not express this pipeline: there was no REST source with session login, no control list from
an API, one fixed bucket per destination, no result write-back, every file was staged on local disk and in staging
(impossible at 160 GiB), and any failed package failed the run. The AI decomposer's split for the requirement on 0.8.2
confirmed it: it put the control list, the login and the write-back into custom source/destination steps, which have
no HTTP client or credentials, and gave the destination one fixed bucket.

- `pkf_runtime/selfservice.py` — due rules, date formats, reasons, study result rules, consecutive-failure limit,
  `submission_data` update, SSAPI GET/PUT.
- trigger ops `selfservice` (receive; the `ack` task writes each due record's result back), `selfservice_due`,
  `data_vars`.
- source type `entimice` (`pkf_runtime/sources/entimice.py`): login per account before any listing, recursive listing,
  streamed gzip-aware download, sessions deleted in every task (also on failure), listing failures fail one study.
- `list` step: `keep_root`, `blank_root`.
- destination: `delivery.mode: stream` (`pkf_runtime/streaming.py`), `bucket_by` / `bucket_map`, steps `check` and
  `prefix_by`; parts grow automatically above ~9 500 parts (16 MiB × 10 000 parts is only 156 GiB).
- Self-Service runs: failed studies do not fail the run (they are recorded in the portal); the run fails on a failed
  control list, an invalid api key, a failed login, or an error outside a single study. The report lists every due
  study and the not-due counts per reason.
- build guards: stream mode (no transformation, a streaming source, S3), Self-Service triggers need
  `max_active_runs: 1`, `custom_delivery` needs one bucket; IAM policy covers every mapped bucket.
- AI guidance: the decomposer's settings guide lists the Entimice source, the Self-Service trigger and the bucket map;
  with it the decomposer splits this requirement into the same shape as the hand-built pipeline.

Recorded AI fixtures: the new catalogue entries change the analyst/decomposer/planner prompts. They were re-keyed with

so components that do not use them keep their prompts and locks.

## Interpretations (please confirm)

- **gzip**: when Entimice sends `Content-Encoding: gzip`, its Content-Length is the compressed size, so the S3 size
  check is skipped for that file (the stored bytes are the decoded original).
- **Today** for the due rules is the UTC date when `read_events` runs.
- **Failed file path** in "S3 upload failed for …" is the Entimice path (`/root/…`).
- **Sessions**: each Airflow task logs in to the accounts it needs and deletes its sessions in a `finally`
  (`plan_packages` logs in to every needed account before listing; each study's `upload` task logs in to its own
  account). Session ids are never put into staging or XCom.
- **Truncated download** (fewer bytes than declared) fails the file with "Other issue".

## Before deploying

Set each environment's values: `triggers/entimice_selfservice.yaml` params (SELF_SERVICE_BASE_URL, FORM_ID, service
user), `sources/entimice_studies.yaml` (ENTIMICE_BASE_URL, accounts by destination, Vault refs),
`destinations/entimice_datalake.yaml` (DESTINATION_BUCKET_MAP), and `PKF_STAGING_URL=s3://…` on the workers. The
values in the files are the local stand-ins. Worker IAM: `s3:PutObject`, `s3:GetObject` (HEAD) and
`s3:AbortMultipartUpload` on both buckets.
